# 分层宪法：规则越写越多，每次只读该读的

[English](LAYERS.md) · 属于 [rule-teeth](README.zh.md)

**一句话**：一条规则的成本 = 它被加载的次数 × 它的长度；它管不管用 = 违反的那一刻，它在不在 AI（或机器）眼前。
所以把每条规则放进**「还能在对的时刻生效」的最便宜的那一层**。这样规则再多，每个 session 的固定成本也不涨；规则再多，也不会因为太多而被忽略。

## 先量一下：真正的固定成本不是根文件

大家都在数 `CLAUDE.md` 有几行。但 AI 每次开工固定要读的，是一整条链：

> **每次必读链** = 根 `CLAUDE.md` + 它的 `@导入`（开工就全部展开，最多四层）+ 不带 `paths:` 的 `.claude/rules/*.md` + **规则里写着「每个 session 都读 X」的那个 X**。

最后一项叫**软导入**。Claude Code 的加载清单里没有它，官方「200 行以内」的建议管不到它，`/context` 也只能在读完之后才看到 —— 但 AI 会照做，所以它是实打实的固定成本。

作者自己的几个仓库，rule-teeth 实测（≈token，中文约 1 字 1 token）：

| 项目 | 根文件 | 每次必读链 | 链上最贵的是什么 |
|---|---:|---:|---|
| 主仓库（16 个子项目） | 3,251 | **14,945** | 根文件写着「每个 session 都读方法论」，方法论又写着「再读派工手册、业务上下文」 |
| 教育项目 | 3,499 | **13,683** | 同一条方法论链 |
| 视频项目 | 1,066 | **16,220** | 根文件列了 5 个「开工先读」的文件 |
| 资料型文件夹 | 3,725 | **42,804** | 一份 36,000 token 的「最先读」文件 |

根文件都在 200 行以内，看起来都「合规」；真正的成本是根文件的 4–15 倍。改造后的数字见文末。

## 五层：每条规则放进最便宜、但还来得及的那层

| 层 | 什么时候进上下文 | 每个 session 的成本 | 靠什么保证执行 | 放什么 | Claude Code 里怎么做 |
|---|---|---|---|---|---|
| **0 牙** | 只在违反的那一刻（拦截信息里带规则原文和出处行号） | 0 | 机器：hook 当场拦 | 能让机器查的：行数、禁用写法、密钥、不许改的文件、不许跑的命令、回复开头、每次必读预算 | `rule_teeth.py init --hook`；测试、CI |
| **1 根** | 每个 session | 最高 | AI 的记性 | 所有子项目都用、任何任务都可能碰到、机器又查不了的规则；子项目索引 | 根 `CLAUDE.md`；共用的一小段用 `@导入` |
| **2 路径** | 碰到相关文件时自动加载 | 只有相关任务付 | 加载时机：正好在要改那里的时候 | 只服务某个子项目、某类文件的规则 | 子目录的 `CLAUDE.md`；`.claude/rules/*.md` + `paths:` |
| **3 触发** | 做某类事时才读 | 只有那类任务付 | 索引里写清「做 Y 时读 X」；skill 的描述 | 流程、清单、长手册、人设 | skill（常驻的只有描述）；文档 + 触发条件 |
| **4 档案** | 从不自动读 | 0 | — | 变更记录、决策史、复盘 | 单独的文件，不被任何「每次都读」指向 |

第 0 层是关键：**拦截信息本身就是按需加载的规则** —— 只在违反的那一刻、只加载违反的那一条、还带着出处。能查的规则装成牙，根里就只需要留一行指针（「不硬编码 key（有牙）」），甚至一行都不留。

第 2 层的好处常被低估：它不只是省 token，还把规则放到了**离违反最近**的时刻。根文件里的第 80 条规则，是在开工时读的，等 AI 真改到那个文件时早就淹没了；带 `paths:` 的规则，是在 AI 读那个文件的那一刻才出现的。

## 一条新规则放哪：问三句

1. **机器能不能查？** 能 → 第 0 层，装成牙，根里最多留一行指针。
   查不了的，先试着改写成**「留下证据」**：「每个重大决策都要反证」查不了；「决策记录里必须有『反证』一节」就能查。牙查的是证据，不是心意。
2. **谁用？** 所有子项目都用 → 根；一个或一部分用 → 第 2 层。**重要不等于通用**：再重要，只有一个子项目用，也下沉。
3. **什么时候用？** 每个任务 → 根或第 2 层；某类任务 → 第 3 层（写清触发条件）；平时不用 → 第 4 层。

拿不准时放低一层。用到的地方多了再往上提 —— 往上提是加一行，往下沉要先找到它，后者难得多。

## 项目越长越大，怎么自动保持（不靠人记）

只写在文档里的规则等于没有规则 —— 「分层」这条规则本身也一样。所以它也要长牙：

1. **每次必读预算**（`load_budget` 牙）。在根文件里写一句，比如：
   `每个 session 固定要读的规则（本文件 + @导入 + 不带 paths 的 .claude/rules + 规则里写着「每个 session 都读」的文件）合计不超过 4,000 token。`
   `rule_teeth.py init --hook` 会把它变成 hook：AI 改规则文件、或者改了一份被「每次都读」的文件之前，先算一遍整条链；**变多了而且超预算就拦下**，拦截信息里列出链上最大的几个文件和省法。本来就超的，只许变少（棘轮）。
2. **根文件体量**（`max_lines` 牙）：「根文件 200 行 / 10KB 以内」。
3. **管规则的规则放第 2 层**：分层方法本身用 `.claude/rules/` + `paths: ["**/CLAUDE.md"]`，只有在改规则文件时才加载 —— 立规矩的时候它正好在眼前，平时一个 token 都不花。
4. **定期体检**（`rule_teeth.py checkup`）：从没被机器查过的规则、该下沉的规则、死指针、写了两遍的规则、检查只覆盖了一部分子项目的规则。
5. **欠条不是豁免**：装牙时已经超的，登记成 30 天到期的欠条，到期自动重新算违规。
6. **AI 不能给自己松绑**：hook 拦下 AI 对 `.rule-teeth/` 和 `.claude/settings*.json` 的修改。预算松不松，人说了算。

预算定多少？没写的时候，体检按 4,000 token 当参考线（大约是官方建议的 200 行，中文）。英文项目可以更低。

## 30 分钟改造一个已有项目

1. `python3 rule_teeth.py checkup /你的项目` —— 先看第一条「每次必读链」。
2. **先砍软导入**：把「每个 session 都读 X」改成「做 Y 时读 X」。如果 X 里确实有几行是每次都要的，把那几行拆成一个小文件。（`@导入` 或 `.claude/rules/` 里的符号链接指到项目外，要先批准一次「外部导入」，没批准就静默不加载 —— 用之前确认它真的加载了。）
3. **根里只服务一个子项目的规则** → 那个子项目自己的 `CLAUDE.md`，或 `.claude/rules/xxx.md` + `paths:`。搬家不改条文，原处留一行指针。
4. **管规则的规则**（分层方法、体量上限）→ `.claude/rules/` + `paths: ["**/CLAUDE.md"]`。
5. 写一句预算，`init --hook` 装牙。
6. 再跑一次 `checkup`，对比前后。

## 常见误区

- **「把规则写短一点就行」** —— 压缩措辞省不了多少，还会丢信息。该做的是搬家，不是压缩。
- **「用 `@导入` 把根文件拆小」** —— 拆了也不省：`@导入` 开工就全展开。它的用处是共用一份真源。
- **「写上『必读』，AI 就会读」** —— 会读，所以它是成本；而且一次读得越多，真正被记住的越少。
- **「重要的规则放根里最保险」** —— 重要不等于通用。能查的规则，放在牙里比放在根里保险得多。

## 改造之后（同一天，同一批仓库）

| 项目 | 改造前 | 改造后 | 少了 |
|---|---:|---:|---:|
| 主仓库（16 个子项目） | 14,945 | **3,737** | −75% |
| 教育项目 | 13,683 | **4,111** | −70% |
| 视频项目 | 16,220 | **2,465** | −85% |
| 方法论文件夹本身 | 7,299 | **4,154** | −43% |

做了什么（主仓库为例）：

- 方法论链从 4 个文件（11,694 token）变成 1 个 1,196 token 的「核心」文件：每个任务都要的只有那十条铁律；人设、派工手册、业务上下文改成「做 Y 时读」。
- 分层规则本身搬进 `.claude/rules/`，`paths:` 指向规则文件：只在改规则的时候加载。
- 只管 Python 的一段搬进 `.claude/rules/`，`paths: ["**/*.py"]`。
- 子项目索引里有 7 格「其它资料」跟各子项目入口文件写的一模一样，删掉。
- 写一句预算，装上牙：之后谁再往链上加东西，超了当场拦。

**没有一条规则被删掉**：全都还在，只是换了层 —— 能查的长了牙，只服务一个子项目的下沉了，按需的写清了触发条件。
资料型文件夹没改：那份大文件是一件正在进行中的事的现行唯一口径，拆不拆由主人决定。工具只负责把数字摆出来。
